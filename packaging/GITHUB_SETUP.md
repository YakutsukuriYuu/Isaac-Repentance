# GitHub setup

Source repository: `YakutsukuriYuu/Isaac-Repentance` (public).

The owner selected public distribution of complete installers. The source repo
contains no original game files, but APK/IPA/DMG artifacts intentionally include
them. Keep the original runtime-input archive in a separate private resource
repository or private object storage. Do not place it in a public source Release.

## Private resource host

Recommended private repository name: `Isaac-Repentance-Runtime`. Create a private
Release such as `runtime-v1` and attach the generated `isaac-j835-runtime-v1.tar.gz`.
The repository only needs a README; do not commit large binary inputs to Git.

For a GitHub Release asset, set `ISAAC_RUNTIME_URL` to its REST asset URL:

```text
https://api.github.com/repos/OWNER/PRIVATE-REPOSITORY/releases/assets/ASSET_ID
```

Use a fine-grained token with **Contents: read** for that private resource repo as
`ISAAC_RUNTIME_TOKEN`. The source repo's automatic `GITHUB_TOKEN` cannot read a
different private repo. Do not paste personal tokens into chat or source files.
Set them in **Settings → Secrets and variables → Actions → Repository secrets**.

A private HTTPS object-storage download URL also works. For a signed URL, set only
`ISAAC_RUNTIME_URL`; ensure it remains valid for the build. The fetch script sends
a bearer token only to `api.github.com` and strips it on cross-host redirects.

The committed lock pins SHA-256, archive size, inventory and core version. Upload
the exact generated bytes; do not re-compress the archive without updating its lock.

## Minimum repository configuration

| Type | Name | Purpose |
| --- | --- | --- |
| Secret | `ISAAC_RUNTIME_URL` | Private archive HTTPS/API download URL |
| Secret | `ISAAC_RUNTIME_TOKEN` | Optional cross-repository read token |
| Variable | `ISAAC_BUILD_ON_PUSH` | Set to `true` after setup to build on `main` pushes |

Source validation needs none of these. Run the installer workflow manually first.
Targets are `all`, `android`, `ios`, and `macos`. Without distribution credentials,
the workflow produces a debug-signed APK, unsigned device IPA, and ad hoc Mac DMGs.
Automatic Releases require the persistent Android signing secrets listed below;
a debug APK remains available in Actions artifacts but cannot be published by
the Release job. Apple distribution credentials are optional for sideload builds.

For a private download failure, run **Actions → Check private runtime access**.
It checks the supplied Actions Secret against account, repository, asset metadata,
and download endpoints. It prints sanitized status information, never the Token,
download URL, redirect URL or raw API responses. A successful local CLI login does
not establish that the separately configured Actions Token has resource access.

## Android release signing

Set these secrets to keep app updates compatible:

- `ANDROID_KEYSTORE_BASE64`: Base64 of your existing persistent keystore.
- `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.

The workflow uses release signing automatically when the keystore is configured.
Keep an independent backup of the key. Turning on the workflow's `signing` input
requires signing credentials rather than silently producing a test build.

## iOS signed exports

The default artifact is for later sideload re-signing. For a cloud-signed export:

Secrets:

- `IOS_CERTIFICATE_BASE64`, `IOS_CERTIFICATE_PASSWORD`: signing `.p12` and password.
- `IOS_PROFILE_BASE64`: provisioning profile for this app and intended devices.
- `IOS_EXPORT_OPTIONS_BASE64`: Base64 of an appropriate Xcode export-options plist.

The workflow derives `APPLE_TEAM_ID` and `IOS_PROVISIONING_PROFILE_SPECIFIER`
from the supplied profile. Optionally set repository variable
`IOS_CODE_SIGN_IDENTITY` if a specific signing identity is needed. Local builds
can supply the team/profile environment variables directly.

The bundle ID is configured in `packaging/mobile/capacitor.config.json`; choose a
matching identifier and profile. A signed artifact's installation scope is
determined by that profile. Cloud building does not bypass iOS signing rules.

The `xcode-27` runner provides the SDK required by the iOS 27 deployment target.
Certificates are installed in a temporary runner keychain and removed afterward.

## macOS signed and notarized exports

Set secrets `MAC_CERTIFICATE_BASE64`, `MAC_CERTIFICATE_PASSWORD`, and
`APPLE_API_KEY_BASE64`. Set variables `APPLE_API_KEY_ID` and `APPLE_API_ISSUER`.
Use a Developer ID certificate and an App Store Connect API key suitable for
notarization. Select `signing=true` when dispatching this workflow.

## First release checks

1. Source validation passes.
2. The private input is fetched without logging its credential or signed URL.
3. All resource checksums pass; no user saves or preinstalled Mods are included.
4. APK/IPA verification inspects the actual installer ZIP contents and hashes.
5. Install on the intended devices, play, save, close, reopen and Continue.
6. Test virtual controls, imported Mods, native DAT exchange, audio and backgrounding.

## Automatic public Releases

A successful full installer build on `main` publishes a public Release tagged
`build-<workflow run number>`. A `v*` tag build publishes under that version tag.
Manual runs with `platform=all` on `main` or a `v*` tag also publish; single-platform
runs keep their output in Actions artifacts and do not create an incomplete Release.
All Android, iOS, and both macOS builds must succeed before publishing.

The publisher downloads only the four installer artifacts from the same run,
requires a release-signed Android APK, and generates `SHA256SUMS.txt`. It creates
a draft, uploads and verifies all five assets, then publishes and marks the Release
as latest. Failed uploads leave a draft; choose **Re-run failed jobs** to resume
publication using the already-built installers. Rebuilding every job may produce
different bytes for the same tag, which the publisher refuses to overwrite.
Existing public assets are verified rather than replaced. Only this final job receives
`contents: write`; it uses the built-in `GITHUB_TOKEN`, so no additional Secret is
needed. Private runtime archives and signing keys are never Release assets.

Players can use [Releases](https://github.com/YakutsukuriYuu/Isaac-Repentance/releases)
or the [latest release](https://github.com/YakutsukuriYuu/Isaac-Repentance/releases/latest)
without signing into GitHub. The APK, IPA, and two DMGs remain available until the
Release/assets are explicitly deleted; the seven-day Actions artifact retention
does not apply to them. The default IPA still requires sideload re-signing, and
default Mac builds are not notarized.

Actions artifacts remain available for seven days for build inspection. Public
Actions builds and private resource downloads may incur storage/transfer costs
under their respective plans; keep independent backups of private inputs and keys.
